# 点播第二阶段

## 1. 文档目标

这份文档把第二阶段已经做过、已经跑通、接下来每天怎么启动，统一整理到一个地方。

第二阶段不是再讨论“点播系统理论上怎么设计”，而是明确当前项目的可执行方案：

- Ubuntu 虚拟机提供服务端能力
- Docker Compose 承载基础设施
- Go 程序负责导入、转码、API
- Qt 客户端只负责拉列表、拉详情、播放 `playUrl`

如果第一阶段基础环境还没有完成，先看：

- [点播第一阶段部署.md](/d:/itffmpeg/av_media/online/duanshipin-pingtai/docs/点播第一阶段部署.md)

整体方案说明见：

- [点播.md](/d:/itffmpeg/av_media/online/duanshipin-pingtai/docs/点播.md)

## 2. 第二阶段边界

第二阶段只做下面这条最小闭环：

1. 在服务端导入一个本地视频
2. 写入 `videos` 和 `transcode_jobs`
3. Worker 处理转码任务
4. 生成 `m3u8 + ts + cover.jpg`
5. 上传到 MinIO
6. API 提供视频列表和详情
7. Qt 客户端请求接口并播放返回的 `playUrl`

第二阶段明确不做：

- Qt 客户端上传视频
- 多码率自适应播放
- 登录鉴权
- 审核流
- CDN
- 复杂推荐和搜索

也就是说，当前第二阶段的重点是：

- 先把“服务端准备视频”
- 再把“客户端播放服务端视频”彻底跑通

## 5. 第二阶段架构图

```text
Windows 宿主机
┌──────────────────────────────────────────────────────────────┐
│ Qt 客户端                                                    │
│                                                              │
│  1. GET /api/videos                                          │
│  2. GET /api/videos/{id}                                     │
│  3. 播放 playUrl 指向的 m3u8                                  │
└──────────────────────────────────────────────────────────────┘
                              |
                              v
Ubuntu 虚拟机 192.168.99.128
┌──────────────────────────────────────────────────────────────┐
│ Docker Compose                                               │
│                                                              │
│  ┌──────────────┐   ┌──────────────┐   ┌──────────────────┐  │
│  │ MySQL        │   │ Redis        │   │ MinIO            │  │
│  │ videos       │   │ 任务占位/缓存 │   │ raw-media        │  │
│  │ transcode... │   │              │   │ vod-media        │  │
│  └──────────────┘   └──────────────┘   │ image-assets     │  │
│                                        └──────────────────┘  │
│                                                              │
│  ┌────────────────┐   ┌────────────────┐   ┌──────────────┐  │
│  │ Importer       │   │ Worker         │   │ API          │  │
│  │ 导入原视频      │   │ 转码/截图/回写  │   │ 列表/详情接口 │  │
│  └────────────────┘   └────────────────┘   └──────────────┘  │
│                                                              │
│                      ┌────────────────┐                      │
│                      │ ffmpeg/ffprobe │                      │
│                      └────────────────┘                      │
└──────────────────────────────────────────────────────────────┘
```

数据流：

1. `Importer` 把原始视频上传到 `raw-media`
2. `Importer` 写 `videos` 和 `transcode_jobs`
3. `Worker` 从 `raw-media` 下载原始视频
4. `Worker` 用 `ffprobe` 读元数据，用 `ffmpeg` 生成 HLS 和封面  `ffmpeg` = 修改/生成媒体文件   `ffprobe` = 检查/读取媒体文件信息
5. `Worker` 把结果上传到 `vod-media` 和 `image-assets`
6. `API` 从 MySQL 读取数据，返回 `playUrl` / `coverUrl`
7. Qt 客户端请求 API，再直接播放 `playUrl`

## 6. 当前代码分工

### 6.1 虚拟机运行目录

实际在虚拟机上运行时，以这个目录为准：

```text
~/vod-platform/server
```

### 6.2 服务端代码结构

```text
server/
├─ cmd/
│  ├─ importer/
│  │  └─ main.go
│  ├─ worker/
│  │  └─ main.go
│  └─ api/
│     └─ main.go
├─ internal/
│  ├─ config/
│  │  └─ config.go
│  ├─ db/
│  │  └─ mysql.go
│  └─ storage/
│     └─ minio.go
└─ go.mod
```

### 6.3 每个程序负责什么

`cmd/importer`

- 接收本地文件路径
- 上传原视频到 `raw-media`
- 写一条 `videos`
- 写一条 `transcode_jobs`

`cmd/worker`

- 找到一条 `pending` 任务
- 下载原视频
- 用 `ffprobe` 获取时长和分辨率
- 用 `ffmpeg` 生成 `index.m3u8`、`.ts`、`cover.jpg`
- 上传结果
- 更新 `videos.status` 和 `transcode_jobs.status`

`cmd/api`

- 提供 `GET /healthz`
- 提供 `GET /api/videos`
- 提供 `GET /api/videos/{id}`

## 14. MinIO 访问要求

当前 API 返回的是 MinIO 直链风格地址。

形式类似：

```text
http://192.168.99.128:9000/vod-media/...
http://192.168.99.128:9000/image-assets/...
```

所以当前阶段必须保证：

- `vod-media` 可匿名读取
- `image-assets` 可匿名读取

而 `raw-media` 不建议开放匿名读取。

否则会出现两类问题：

- Qt 拉到了 `playUrl`，但播放器打不开
- 首页有 `coverUrl`，但封面显示不出来

## 16. 当前限制

### 16.1 Worker 不是常驻服务

当前 Worker 不是循环监听模式，而是手动执行一次处理一条任务。

这对第二阶段原型没有问题，但不适合后续正式使用。

### 16.2 API 直接返回对象存储地址

当前没有经过 Nginx 统一代理，也没有签名 URL。

优点：

- 简单
- 便于先打通链路

缺点：

- 地址暴露的是 MinIO
- 权限控制还比较粗

### 16.3 当前没有上传接口

第二阶段明确接受这个现实：

- 当前客户端没有上传
- 当前视频进入系统的方式是服务端导入

这不是问题，而是当前阶段的设计前提。

### 16.4 当前 UI 状态展示还很基础

目前首页还没有完整展示：

- 转码中
- 转码失败
- 封面加载失败
- 空列表提示

这些属于下一步体验增强项。

## 17. 常见问题

### 17.1 `go build` 又走回旧版本

现象：

- 报 `cmp`、`maps`、`slices`、`iter` 不存在

原因：

- 终端没有使用 `/usr/local/go/bin/go`

处理：

```bash
export PATH=/usr/local/go/bin:$PATH
hash -r
which go
go version
```

### 17.2 `ffmpeg` 命令异常

如果之前装过手工下载的损坏版 `ffmpeg`，会出现共享库错误。

当前正确做法是使用：

- `/usr/bin/ffmpeg`
- `/usr/bin/ffprobe`

### 17.3 Docker 镜像拉取失败

如果出现 `connect: connection refused` 或无法访问镜像仓库：

- 先确认虚拟机可以联网
- 再确认 Docker 是否配置了可用镜像源

### 17.4 端口冲突

你前面已经遇到过：

- Redis 的 `6379` 被占用
- MySQL 的 `3306` 可能和现有实例冲突

当前解决方式是：

- Redis 映射为 `6380:6379`
- MySQL 映射为 `3307:3306`

### 17.5 Qt 拉到接口但播放失败

优先检查四件事：

1. `GET /api/videos/{id}` 里的 `status` 是否为 `ready`
2. `playUrl` 是否能在浏览器中访问
3. `vod-media` 是否允许匿名读
4. Qt 播放器当前环境是否支持该 HLS 地址

## 21. 当前最短命令清单

如果你后面只想快速翻这一节，可以直接看这里。

### 21.1 启动基础设施

```bash
cd ~/vod-platform
docker compose up -d
```

### 21.2 启动 API

```bash
cd ~/vod-platform/server
export PATH=/usr/local/go/bin:$PATH
hash -r
go run ./cmd/api
```

### 21.3 导入视频

```bash
cd ~/vod-platform/server
export PATH=/usr/local/go/bin:$PATH
hash -r
go run ./cmd/importer -file /home/lq/media/xxx.mp4 -title "标题" -desc "描述"
```

### 21.4 跑 Worker

```bash
cd ~/vod-platform/server
export PATH=/usr/local/go/bin:$PATH
hash -r
go run ./cmd/worker
```

### 21.5 验证 API

```bash
curl http://127.0.0.1:8080/healthz
curl http://127.0.0.1:8080/api/videos
curl http://127.0.0.1:8080/api/videos/1
```
