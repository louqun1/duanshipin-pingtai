# VideoPlayerWindow 全屏悬浮控制栏实现说明

## 1. 这次要解决什么问题

这次改动的目标不是单纯“加一个全屏按钮”，而是一次性把下面几件事打通：

- 播放窗口支持进入/退出全屏
- 全屏状态下，鼠标移动时，底部浮现半透明控制栏
- 控制栏里包含播放/暂停、进度条、音量调节、全屏切换
- 尽量复用窗口态和全屏态的控件与样式，减少两套 UI 带来的重复代码

本次主要改动文件：

- `frontend/widgets/VideoPlayerWindow.hpp`
- `frontend/widgets/VideoPlayerWindow.cpp`

这次没有改 `PlayerController` 的职责边界。

## 2. 这次的核心思路

### 2.1 一套控件，两种展示行为

这次没有为全屏再单独做一套“全屏版播放栏”，而是把播放按钮、进度条、时间文本、静音按钮、音量 slider、全屏按钮统一收进同一个 `controlBar_`。

也就是说：

- 窗口态：这组控件始终显示在视频区域底部
- 全屏态：还是同一组控件，只是改成悬浮在视频上，并且由鼠标移动触发显示/自动隐藏

这样做的好处是：

- 播放逻辑只接一套按钮和 slider
- 样式只维护一套
- 后续改文案、改布局、改主题时不会出现双份代码不同步

### 2.2 全屏不是新窗口逻辑，而是窗口模式切换

这次把全屏处理收口到了 `VideoPlayerWindow` 自己内部：

- `toggleFullscreen()`
- `setFullscreen(bool fullscreen)`
- `applyWindowMode(bool fullscreen)`

进入全屏时，做的事情主要是：

- 隐藏顶部 header
- 隐藏右侧 side panel
- 让视频区域铺满窗口
- 保留同一套控制栏作为视频上的 overlay

退出全屏时，再把窗口态布局恢复回来。

这样能保证：

- 全屏只改变展示方式
- 不影响 `PlayerController`、播放状态、进度同步、音量控制

### 2.3 保持 PlayerController 的职责边界

这次虽然加的是全屏 UI，但我还是延续了前面的架构边界：

- `VideoPlayerWindow` 负责展示和交互
- `PlayerController` 负责播放命令和状态同步

所以控制栏里的交互仍然走原来的高层接口：

- 播放/暂停：`requestTogglePlayback()`
- seek：`requestSeek(positionMs)`
- 音量：`requestSetVolume(volume)`
- 静音：`requestToggleMute()`

这样全屏和非全屏不会出现两套播放逻辑分叉的问题。

## 3. 全屏交互是怎么工作的

### 3.1 进入/退出全屏的入口

现在支持几种切换方式：

- 点击控制栏里的 `Fullscreen` 按钮
- 在视频区域双击
- 按 `F` 或 `F11`
- 全屏时按 `Esc` 退出

这样既有按钮入口，也有符合播放器习惯的快捷操作。

### 3.2 鼠标移动时浮现底部控制栏

这次没有把“浮现”做成完全独立的新控件，而是给现有 `controlBar_` 增加了：

- `QGraphicsOpacityEffect`
- `QPropertyAnimation`
- `QTimer`

逻辑是：

1. 鼠标进入、移动、点击或滚轮时，显示控制栏
2. 在全屏模式下，启动一个延时隐藏计时器
3. 到时间后，如果用户没有在拖动进度条，也没有把鼠标停在控制栏上，就淡出隐藏
4. 用户再次移动鼠标时，再次淡入显示

这样做的重点是：

- 控制栏是“同一个控件”
- 浮现/隐藏只是它的可见性和透明度变化

### 3.3 拖动进度条时不自动隐藏

如果用户正在拖动进度条，控制栏不应该突然消失。

所以这次继续复用了已有的 `isSliderScrubbing_` 状态，在全屏自动隐藏时加了一层保护：

- 拖动中：不隐藏
- 松手后：恢复自动隐藏计时

这能避免全屏 seek 的操作体验被打断。

## 4. 为什么样式能复用

这次专门把几类样式收成了函数，而不是把窗口态和全屏态分别写两份：

- `overlayCardStyle()`
- `primaryControlButtonStyle()`
- `secondaryControlButtonStyle()`
- `sliderStyle(...)`

这意味着：

- 播放按钮、静音按钮、全屏按钮共用同一套按钮风格
- 进度条和音量条共用同一个 slider 样式生成逻辑
- 全屏悬浮栏和窗口态控制栏直接共用同一个半透明面板样式

如果后面你决定：

- 全部统一成一套视觉
- 或者只微调全屏态透明度、圆角、间距

都可以继续沿着这套结构改，而不用把两套 UI 重写一遍。

## 5. 这次布局上的调整

为了让控制栏真正悬浮在视频上，这次把播放器区域改成了“视频视口 + overlay”的结构：

- `videoSurfaceWidget_` 负责画面
- `topOverlayWidget_` 负责视频标题/提示
- `controlBar_` 负责底部播放控制

它们都挂在同一个 `videoViewport_` 上。

这样做之后：

- 窗口态下，控制栏看起来像贴在视频底部
- 全屏态下，控制栏自然就是悬浮层，不需要额外搬运控件

## 6. 当前方案的优点

- 全屏和非全屏共用一套控制控件，重复代码少
- 不破坏 `PlayerController` 的职责边界
- 用户交互比较符合播放器习惯：双击、Esc、F11、鼠标唤起控制栏
- 控制栏隐藏逻辑和进度条拖动状态能协同工作
- 后续如果要继续做图标、动画、手势，扩展点比较清晰

## 7. 后面还可以继续优化什么

这次已经把结构搭稳了，但还有几处可以继续打磨：

- 把文字按钮替换成真正的图标按钮
- 全屏时在控制栏隐藏后顺带隐藏鼠标指针
- 给顶部信息层也加淡入淡出，而不是只控制底部栏
- 给进度条增加 hover 预览时间点
- 给音量增加弹出式或纵向调节条

## 8. 这次方案的结论

这次不是“额外再做一个全屏播放器 UI”，而是把 `VideoPlayerWindow` 调整成：

- 以 `videoViewport_` 为核心的视频容器
- 复用同一套控制栏
- 在全屏下通过事件 + 定时器 + 透明度动画实现悬浮显示

如果用一句话概括这次思路，就是：

全屏和窗口态共享同一套播放控件，只改变布局和显示策略，不复制播放控制逻辑。
