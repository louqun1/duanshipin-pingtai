# 直播 HTTP-FLV 主链路实现说明

## 1. 这份文档解决什么问题

这份文档只解释当前项目里这条最小直播观看主链路：

`RTMP 开播 -> 服务端转 HTTP-FLV -> Qt 客户端读取 HTTP-FLV -> FLV demux -> 直播页观测状态`

重点不是完整直播系统，也不是多人连麦，而是把当前项目里“观看直播”这条链路真正讲清楚：

- 推流地址到底是什么
- 看播地址到底是什么
- `192.168.99.128` 这个实际例子应该怎么用
- 代码现在到底做到哪里
- 下一步你应该把哪一段接到自己的解码和渲染链路里

---

## 2. 一个实际例子：192.168.99.128 怎么推，怎么拉，页面里填什么

假设你的 Ubuntu 虚拟机 IP 是：

```text
192.168.99.128
```

并且这台机器上已经跑了直播服务器，能接 RTMP、出 HTTP-FLV。

那就先固定用这一组地址：

```text
RTMP 推流地址
rtmp://192.168.99.128/live/room1

HTTP-FLV 看播地址
http://192.168.99.128:8080/live/room1.flv
```

这里最关键的一点是：

- `rtmp://192.168.99.128/live/room1`
  这是推流地址，给 OBS / FFmpeg 用
- `http://192.168.99.128:8080/live/room1.flv`
  这是看播地址，给播放器和直播页面用

不要把这两个地址写反。

### 2.1 你可以把整条链路理解成这样

```text
Windows 上的 OBS / FFmpeg
    -> 推到 rtmp://192.168.99.128/live/room1

Ubuntu 虚拟机上的直播服务器
    -> 把这路流转成 http://192.168.99.128:8080/live/room1.flv

Qt 客户端直播页
    -> 填 http://192.168.99.128:8080/live/room1.flv
    -> 点击 Start Watch
```

### 2.2 如果你用 FFmpeg 做测试推流

假设 Windows 本地有一个测试文件：

```text
D:\test\input.mp4
```

那么可以这样推：

```bash
ffmpeg -re -stream_loop -1 -i D:\test\input.mp4 -c:v libx264 -c:a aac -f flv rtmp://192.168.99.128/live/room1
```

这条命令的意思是：

- `-re`
  按实时速度推
- `-stream_loop -1`
  无限循环推，方便测试
- `-f flv`
  用 FLV 封装发给 RTMP
- 最后的 `rtmp://192.168.99.128/live/room1`
  就是实际推流地址

### 2.3 如果你用 OBS 做测试推流

OBS 里可以这样填：

```text
服务端 Server:
rtmp://192.168.99.128/live

串流密钥 Stream Key:
room1
```

OBS 最终拼出来的完整推流地址，就是：

```text
rtmp://192.168.99.128/live/room1
```

### 2.4 推起来之后怎么验证服务端真的有流

先不要急着进 Qt 页面。

先用外部播放器验证一下 HTTP-FLV 看播地址：

```bash
ffplay http://192.168.99.128:8080/live/room1.flv
```

如果这一步已经能看到画面，就说明：

- RTMP 推流进服务端成功
- 服务端 HTTP-FLV 输出成功
- 看播地址是通的

这时候再进 Qt 页面，问题范围就会小很多。

### 2.5 在你当前项目里应该怎么填

直播页里应该填：

```text
http://192.168.99.128:8080/live/room1.flv
```

当前代码里默认值也已经改成这个地址了。

点击 `Start Watch` 后，你应该预期看到这样的状态变化：

```text
Idle
-> Connecting
-> Reading
-> Playing
```

### 2.6 你应该在日志里看到什么

理想情况下，日志会依次出现这些关键信息：

1. `HTTP-FLV GET http://192.168.99.128:8080/live/room1.flv`
2. `HTTP response received`
3. `FLV header validated`
4. `First script tag arrived ...`
5. `First audio tag arrived ...`
6. `First video tag arrived ...`
7. `AAC sequence header observed ...`
8. `AVC sequence header observed ...`

这说明链路已经通到：

```text
HTTP 读流
-> FLV 解析
-> Audio / Video / Script Tag 分流
```

### 2.7 如果页面里看不到流，先按这个顺序排查

1. 先确认推流工具是不是在推：
   `rtmp://192.168.99.128/live/room1`
2. 再确认外部播放器能不能播：
   `http://192.168.99.128:8080/live/room1.flv`
3. 如果 `ffplay` 都播不了，问题在服务端，不在 Qt 客户端
4. 如果 `ffplay` 能播，但 Qt 页面不行，就看日志停在了哪一步
5. 如果停在 `Connecting`，通常是 URL、端口或网络不通
6. 如果到了 `Reading`，但迟迟没有 `FLV header validated`，通常是服务端返回的内容不是标准 HTTP-FLV
7. 如果已经看到 `audio/video tag`，说明主链路已经通到播放器内核入口了，下一步就是你自己的解码和渲染

## 3. 当前代码入口

### 3.1 播放控制入口

- `backend/liveplayer/service/LivePlayerController.hpp`
- `backend/liveplayer/service/LivePlayerController.cpp`

职责：

- 给 UI 暴露最小直播控制接口
- 接收 `openStream(url)` / `stopStream()`
- 把 `LivePlayerSession` 的状态和日志转成页面能消费的信号

### 3.2 直播会话层

- `backend/liveplayer/session/LivePlayerSession.hpp`
- `backend/liveplayer/session/LivePlayerSession.cpp`

职责：

- 管理一次 HTTP-FLV 观看会话
- 组织 `HttpFlvStreamReader -> FlvDemuxer -> tag 分流`
- 维护最小状态：`Idle / Connecting / Reading / Playing / Stopped / Error`

### 3.3 协议读取层

- `backend/liveplayer/protocol/HttpFlvStreamReader.hpp`
- `backend/liveplayer/protocol/HttpFlvStreamReader.cpp`

职责：

- 发起 HTTP 请求
- 持续读取流式返回的数据块
- 把每个 chunk 往上交给会话层

### 3.4 FLV 解析层

- `backend/liveplayer/protocol/FlvTypes.hpp`
- `backend/liveplayer/protocol/FlvDemuxer.hpp`
- `backend/liveplayer/protocol/FlvDemuxer.cpp`

职责：

- 校验 FLV Header
- 增量解析 FLV Tag Header / Payload / PreviousTagSize
- 产出 `FlvTag`

### 3.5 页面入口

- `frontend/pages/StreamPage/StreamPage.hpp`
- `frontend/pages/StreamPage/StreamPage.cpp`

职责：

- 提供 HTTP-FLV URL 输入
- 展示开始 / 停止控制
- 展示状态、统计和学习日志

## 4. 当前客户端整体链路

```text
StreamPage
    -> LivePlayerController
    -> LivePlayerSession
    -> HttpFlvStreamReader
    -> FlvDemuxer
    -> FlvTag(script/audio/video)
    -> 日志 / 统计 / 状态
    -> 后续接入 decoder / render
```

可以把它理解成：

- `HttpFlvStreamReader`
  负责把字节读进来
- `FlvDemuxer`
  负责把字节拆成 FLV Tag
- `LivePlayerSession`
  负责理解这些 Tag 是什么，以及下一步应该怎么走

---

## 5. 当前已经补上的关键点

### 5.1 HTTP-FLV 持续读取

`HttpFlvStreamReader` 当前已经能做下面几件事：

- 发起 `GET http://...flv`
- 读取响应头
- 持续接收 `readyRead` 数据块
- 把每个 chunk 通过 `dataChunkReceived(chunk)` 往上抛

这一步最关键的理解是：

- HTTP-FLV 不是一次性下载完整文件
- 它是连接建立后持续有新字节到达
- 所以上层必须支持“不完整数据分段到达”

### 5.2 FLV Header 校验

`FlvDemuxer::parseFlvHeader()` 当前已经做了：

- 校验签名是否是 `FLV`
- 读取 `DataOffset`
- 等 `Header + PreviousTagSize0` 完整到齐后再进入 tag 解析

### 5.3 FLV Tag 增量解析

`FlvDemuxer::pushBytes()` 当前已经补齐了关键 tag 拆分逻辑：

```text
buffer 累积字节
    -> 读取 11 字节 Tag Header
    -> 解析 TagType / DataSize / Timestamp
    -> 等待完整 Payload 到齐
    -> 读取结尾 4 字节 PreviousTagSize
    -> 校验 PreviousTagSize == 11 + DataSize
    -> 产出 FlvTag
```

当前 `FlvTag` 里已经有这些关键字段：

- `type`
- `timestampMs`
- `dataSize`
- `previousTagSize`
- `payload`
- `rawTagType`
- `videoFrameType`
- `videoCodecId`
- `avcPacketType`
- `audioSoundFormat`
- `aacPacketType`
- `isSequenceHeader`
- `isKeyframe`

这意味着你现在已经能在客户端区分：

- script / audio / video tag
- AVC sequence header 和普通视频 tag
- AAC sequence header 和普通音频 tag
- 关键帧和非关键帧

### 5.4 Script / Audio / Video Tag 分流

`LivePlayerSession::drainParsedTags()` 当前已经会做：

- Script Tag
  - 记录第一次 metadata 到达
- Audio Tag
  - 记录第一次 audio tag 到达
  - 记录第一次 AAC sequence header 到达
- Video Tag
  - 记录第一次 video tag 到达
  - 记录第一次 AVC sequence header 到达

### 5.5 当前状态推进逻辑

当前状态流转如下：

```text
Idle
  -> Connecting   open(url)
  -> Reading      HTTP 已连接，等待 FLV Header / Tag
  -> Playing      已经观察到 audio/video 媒体 tag 在流动
  -> Stopped      stop() 或连接结束
  -> Error        HTTP 或 demux 失败
```

这里要特别说明：

当前 `Playing` 的意思是：

> 客户端已经成功收到并解析出了媒体 tag，说明“直播观看主链路已经通到播放器内核入口”。

它现在还不等于：

- 已经解码出 `AVFrame`
- 已经真正渲染出首帧
- 已经真正听到声音

这是当前阶段故意保留的边界。

## 7. 当前故意没有继续写满的部分

下面这几块，是刻意留给你自己继续补的：

### 7.1 Script Tag 深解析

当前没有继续做：

- AMF0 / AMF3 解析
- 提取 metadata 字段

后续你可以自己补：

- `onMetaData`
- `videocodecid`
- `audiocodecid`
- `width`
- `height`

### 7.2 解码器接入

当前没有继续做：

- H.264 Annex-B / AVCC 整理
- AAC AudioSpecificConfig 提取
- 把 tag 送入 FFmpeg 解码器
- 输出 `AVFrame`

这是你最推荐自己写的下一步。

### 7.3 渲染

当前没有继续做：

- 视频首帧回调
- 音频播放
- Qt surface 真正显示

当前页面上的 viewport 还是“解码后要落点的目标面板”。

## 8. 下一步最建议你亲手写什么

建议优先顺序如下：

### 第一步：接视频解码入口

在 `LivePlayerSession::drainParsedTags()` 里，把：

- `video tag`
- `AVC sequence header`
- 普通 `AVC NALU`

送进你自己的视频解码输入队列。

### 第二步：接音频解码入口

同样把：

- `AAC sequence header`
- 普通 AAC raw data

送进你的音频解码输入队列。

### 第三步：把首帧真正接回页面

等你拿到解码后的帧后，再把：

- 首帧到达
- 当前帧尺寸
- 视频刷新回调

接回 `StreamPage` 或你后续的直播渲染控件。
