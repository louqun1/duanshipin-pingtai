# 直播 HTTP-FLV 主链路实现说明

## 1. 这份文档现在描述什么

这份文档描述的是当前仓库里已经接上的直播 HTTP-FLV 观看主链路。

这次要先把范围说清楚：

- 当前仓库负责的是 Qt 客户端看播侧
- 外部直播服务器负责 `RTMP ingest -> HTTP-FLV output`
- 当前直播页默认主链已经不是 `FFPlayer / IjkMediaPlayer` 直连
- 当前直播页默认主链已经切回你自己的学习链路：

```text
HttpFlvStreamReader
-> QByteArray chunk
-> FlvDemuxer
-> FlvTag(script/audio/video)
-> FlvVideoDecoder(当前只接 H.264 video)
-> AVFrame
-> LivePlayerSession::handleDecodedVideoFrame()
-> VideoOpenGLWidget::presentFrame()
```

也就是说，当前文档不再描述“把 HTTP-FLV URL 直接交给黑盒播放器内核”的方案，而是描述你现在真正能学习到 `chunk / tag / decode / render` 的这条链路。

同时也要明确当前阶段边界：

- 已完成：`HTTP chunk -> FLV tag -> H.264(ffmpeg) -> 视频渲染`
- 未完成：AAC 解码、音频输出、packet/frame queue、A/V sync、抖动缓冲

## 2. 当前真实主链路

### 2.1 从页面点击到开始看播

```text
startButton_ = new QPushButton("Start Watch", sidePanel);
--clicked-->
lambda in StreamPage::connectController()
-> LivePlayerController::openStream(url)
-> LivePlayerSession::open(url)
-> HttpFlvStreamReader::open(url)
-> QNetworkAccessManager::get(request)
-> QNetworkReply::readyRead()
-> HttpFlvStreamReader::handleReadyRead()
-> emit dataChunkReceived(chunk)
-> LivePlayerSession::handleReaderDataChunk(chunk)
```

这里的关键变化是：

- 不再把 URL 交给 `IjkMediaPlayer`
- 不再让 `FFPlayer` 负责 `avformat_open_input() / av_read_frame()`
- 而是先由 Qt 网络层持续拿到 HTTP-FLV 字节流

如果你想在代码里顺着找，真实入口是：

- `frontend/pages/StreamPage/StreamPage.cpp`
  - 创建按钮：`QPushButton("Start Watch`
  - 信号绑定：`connect(startButton_, &QPushButton::clicked, ...)`
- `backend/liveplayer/service/LivePlayerController.cpp`
  - `openStream(url)`
- `backend/liveplayer/session/LivePlayerSession.cpp`
  - `open(url)`
- `backend/liveplayer/protocol/HttpFlvStreamReader.cpp`
  - `HttpFlvStreamReader::open(const QUrl &url)`
  - `handleReadyRead()`

### 2.2 chunk 怎么变成 tag

```text
QNetworkReply::readyRead()
-> reply->readAll()
-> QByteArray chunk
-> FlvDemuxer::pushBytes(chunk, report)
-> 校验 FLV Header
-> 增量解析 Tag Header / Payload / PreviousTagSize
-> 产出 FlvTag
-> LivePlayerSession::drainParsedTags()
```

这里你现在能直接观察到：

- HTTP 是否连上
- FLV Header 是否通过
- script/audio/video tag 是否真的在流动
- AAC / AVC sequence header 是不是已经到达

### 2.3 video tag 怎么走到 FFmpeg 解码器

当前只接了视频第一阶段，而且只接了 AVC/H.264：

```text
FlvTag(type=Video)
-> FlvVideoDecoder::pushTag(tag)
-> 如果 avcPacketType == 0
   -> 取 AVCDecoderConfigurationRecord
   -> avcodec_find_decoder(H264)
   -> avcodec_alloc_context3()
   -> avcodec_open2()

-> 如果 avcPacketType == 1
   -> 取 FLV video payload 里的 AVC NALU 数据
   -> avcodec_send_packet()
   -> avcodec_receive_frame()
   -> Frame callback
```

这一步不是完整直播播放器内核，只是你当前学习里程碑的第一小步：

- 先把手写 `chunk/tag` 真正接进 FFmpeg 视频解码
- 先把第一帧视频跑通
- 先确认“你真的接管了解码入口”

### 2.4 AVFrame 怎么走到页面渲染

```text
FlvVideoDecoder frame callback
-> LivePlayerSession::handleDecodedVideoFrame(frame)
-> 必要时 sws_scale -> YUV420P
-> VideoOpenGLWidget::presentFrame()
```

如果解码出的像素格式已经是 `YUV420P`，当前会直接复制三个平面。

如果不是 `YUV420P`，当前会：

- 用 `sws_getCachedContext()`
- 转成 `YUV420P`
- 再交给 `VideoOpenGLWidget`

所以当前页面真正看到画面的链路已经是：

```text
HTTP chunk
-> FLV tag
-> H.264 decode
-> AVFrame
-> OpenGL render
```

而不是“日志里说在播，但其实还是黑盒播放器在做解码”。

### 2.5 以 `192.168.99.128` 为例，从点击观看到播放的整条链路

假设外部直播服务器地址是：

```text
RTMP ingest:
rtmp://192.168.99.128/live/room1

HTTP-FLV watch:
http://192.168.99.128:8080/live/room1.flv
```

那么当前这版代码里，从“点击观看”到“页面出第一帧”的完整链路可以写成：

```text
外部推流端(OBS / FFmpeg)
-> rtmp://192.168.99.128/live/room1

外部直播服务器
-> 把 RTMP 流转成 HTTP-FLV
-> http://192.168.99.128:8080/live/room1.flv

Qt 页面输入框
-> 填 http://192.168.99.128:8080/live/room1.flv

用户点击 "Start Watch"
-> QPushButton::clicked
-> StreamPage::connectController() 里的 lambda
-> livePlayerController_.openStream(liveUrl)

LivePlayerController
-> LivePlayerController::openStream(url)
-> session_->open(url)

LivePlayerSession
-> LivePlayerSession::open(url)
-> reader_->open(QUrl(url))
-> 状态: Idle -> Connecting

HttpFlvStreamReader
-> QNetworkAccessManager::get()
-> 发起 GET http://192.168.99.128:8080/live/room1.flv
-> 收到 HTTP 响应头
-> emit connected(contentType, statusCode)

LivePlayerSession
-> handleReaderConnected(contentType, statusCode)
-> 状态: Connecting -> Reading

QNetworkReply
-> readyRead()

HttpFlvStreamReader
-> handleReadyRead()
-> reply->readAll()
-> emit dataChunkReceived(chunk)

LivePlayerSession
-> handleReaderDataChunk(chunk)
-> bytesReceived_ += chunk.size()
-> demuxer_.pushBytes(chunk, report)

FlvDemuxer
-> parseFlvHeader(report)
-> 增量解析 FLV tag
-> takeNextTag(tag)

LivePlayerSession
-> drainParsedTags()
-> script tag: 记日志 / 计数
-> audio tag: 记日志 / 计数 / 提示 AAC TODO
-> video tag: 调 videoDecoder_.pushTag(tag)

FlvVideoDecoder
-> pushTag(tag)
-> 如果是 AVC sequence header
   -> handleAvcSequenceHeader()
   -> avcodec_find_decoder(H264)
   -> avcodec_alloc_context3()
   -> avcodec_open2()

-> 如果是 AVC NALU tag
   -> handleAvcNaluTag()
   -> submitVideoPacket()
   -> avcodec_send_packet()
   -> avcodec_receive_frame()
   -> frame callback

LivePlayerSession
-> handleDecodedVideoFrame(frame)
-> 必要时 sws_scale -> YUV420P
-> invokeMethod(videoSurface, "presentFrame", ...)
-> 状态: Reading -> Playing

VideoOpenGLWidget
-> presentFrame()
-> paintGL()
-> 页面出现第一帧
```

这条链路里，当前真正表示“视频已经播起来”的关键节点不是：

- 收到 HTTP 响应头
- FLV Header 校验通过
- 收到 video tag

而是：

```text
FlvVideoDecoder
-> avcodec_receive_frame()
-> LivePlayerSession::handleDecodedVideoFrame()
-> VideoOpenGLWidget::presentFrame()
```

也就是“已经真的解码出一帧 AVFrame，并且交给页面渲染”。

## 3. 当前状态怎么推进

### 3.1 状态流转

当前直播会话状态大致是：

```text
Idle
-> Connecting
   LivePlayerSession::open(url)

-> Reading
   HTTP 已连接，等待 FLV Header / 媒体 tag

-> Playing
   第一帧 H.264 视频已经成功解码

-> Stopped
   stop() 或 HTTP 流结束

-> Error
   HTTP / demux / decode 出错
```

### 3.2 `Playing` 在当前版本里的准确含义

当前 `Playing` 的触发点不是“看到 video tag 在流动”，而是：

```text
FlvVideoDecoder 成功产出第一帧 AVFrame
```

所以现在的 `Playing` 比之前更严格，表示的是：

- 不是只到 tag 层
- 不是只到 sequence header
- 而是真的至少走通了一次视频解码

但它依然还不等于：

- 音频也已经正常输出
- 音视频已经同步

因为当前版本还没有把 AAC decode / audio output / A/V sync 补完。

## 4. 当前代码入口

### 4.1 播放控制入口

- `backend/liveplayer/service/LivePlayerController.hpp`
- `backend/liveplayer/service/LivePlayerController.cpp`

职责：

- 对页面暴露 `openStream(url)` 和 `stopStream()`
- 转发会话状态、日志、统计到 UI

### 4.2 直播会话层

- `backend/liveplayer/session/LivePlayerSession.hpp`
- `backend/liveplayer/session/LivePlayerSession.cpp`

职责：

- 组织整条直播观看主链
- 管理 `HttpFlvStreamReader`
- 管理 `FlvDemuxer`
- 管理 `FlvVideoDecoder`
- 接收 `AVFrame` 并交给 `VideoOpenGLWidget`
- 维护状态、日志、统计

### 4.3 HTTP 读流层

- `backend/liveplayer/protocol/HttpFlvStreamReader.hpp`
- `backend/liveplayer/protocol/HttpFlvStreamReader.cpp`

职责：

- 发起 HTTP GET
- 持续接收 `readyRead`
- 把每个 `chunk` 往上层抛
- 把网络错误往上层抛

### 4.4 FLV 增量解析层

- `backend/liveplayer/protocol/FlvTypes.hpp`
- `backend/liveplayer/protocol/FlvDemuxer.hpp`
- `backend/liveplayer/protocol/FlvDemuxer.cpp`

职责：

- 校验 FLV Header
- 增量解析 Tag Header / Payload / PreviousTagSize
- 产出 `FlvTag`

当前已经能识别：

- script / audio / video tag
- AVC sequence header
- AAC sequence header
- keyframe

### 4.5 视频解码桥

- `backend/liveplayer/decode/FlvVideoDecoder.hpp`
- `backend/liveplayer/decode/FlvVideoDecoder.cpp`

职责：

- 接 video tag
- 从 AVC sequence header 初始化 H.264 decoder
- 从 AVC NALU tag 调 `avcodec_send_packet / receive_frame`
- 把解码出的帧通过 callback 回传

当前边界：

- 只接 `videoCodecId == 7`，也就是 AVC/H.264
- 只做视频
- 不做音频
- 不做独立 packet queue
- 不做时钟同步

### 4.6 页面入口

- `frontend/pages/StreamPage/StreamPage.hpp`
- `frontend/pages/StreamPage/StreamPage.cpp`

职责：

- 输入 HTTP-FLV URL
- 点击 `Start Watch / Stop`
- 展示状态、日志、统计
- 挂接 `VideoOpenGLWidget`

### 4.7 视频渲染入口

- `frontend/widgets/VideoOpenGLWidget.hpp`
- `frontend/widgets/VideoOpenGLWidget.cpp`

职责：

- 接 `YUV420P` 三平面
- 做颜色空间矩阵转换
- 在 OpenGL widget 上显示视频

## 5. 当前页面和日志应该怎么看

### 5.1 页面统计区现在表示什么

当前统计区重新接回来了，不再是全 0 的占位状态。

现在会显示：

- `bytesReceived`
- `scriptTagCount`
- `audioTagCount`
- `videoTagCount`

所以你现在能直接看出：

- HTTP 是否真的在持续下发数据
- tag 是否真的被拆出来
- audio/video/script 三类数据有没有在流动

### 5.2 日志现在最值得观察什么

当前日志重点不是 “FFPlayer prepared/playing” 这类黑盒事件，而是这些学习型日志：

1. `HTTP-FLV GET ...`
2. `HTTP response received ...`
3. `Received first payload chunk ...`
4. `FLV header validated ...`
5. `First script tag arrived ...`
6. `First audio tag arrived ...`
7. `First video tag arrived ...`
8. `AVC sequence header observed ...`
9. `Manual live video path reached the first decoded frame.`

这条日志链更适合你学习：

```text
网络字节
-> FLV 拆包
-> 视频 sequence header
-> 视频普通 NALU
-> 第一帧解码成功
```

## 6. 当前明确没有做完的部分

这一部分要写清楚，不然很容易误以为“直播已经完整跑通”。

### 6.1 音频还没有真正接入 FFmpeg 解码输出链

当前音频 tag 只做到：

- 计数
- 识别第一条 audio tag
- 识别 AAC sequence header
- 打日志提示你下一步要做什么

当前还没有做到：

- 从 AAC sequence header 初始化 AAC decoder
- 把 AAC raw payload 喂给 `avcodec_send_packet`
- 真正产出音频帧
- 音频设备输出

### 6.2 还没有单独的 packet/frame queue

当前视频解码是“收到 tag 就立刻 decode”：

```text
tag
-> decoder
-> frame
```

这很适合第一阶段学习，但还不是完整直播播放器架构。

后续如果你要继续学习更接近播放器内核的结构，应该自己补：

- video packet queue
- audio packet queue
- decoded frame queue
- 丢帧 / 背压 / 缓冲控制

### 6.3 还没有 A/V sync

当前还没有：

- audio clock
- video clock
- master clock
- 根据 PTS 控制渲染节奏
- 音画同步策略

所以现在这版更准确的定位是：

> 直播 HTTP-FLV 观看主链的“视频第一阶段学习版”

而不是完整直播播放器。

## 7. 你下一步最适合亲手写什么

下面这几段我建议你自己手写，不要让我直接替你一把梭写完。

### 里程碑 1：补 AAC 解码入口

你应该自己补：

- 从 audio tag 里区分 AAC sequence header 和 AAC raw
- 从 sequence header 提取 AudioSpecificConfig
- 初始化 AAC decoder
- 把普通 AAC payload 喂给 FFmpeg

建议你重点手写位置：

- `LivePlayerSession::drainParsedTags()`
- 新建一个和 `FlvVideoDecoder` 对应的音频 decoder 类

### 里程碑 2：补音频输出

你应该自己决定和手写：

- 用什么音频设备层输出
- 是先接 Qt，还是先接 SDL，还是别的抽象
- 音频缓冲怎么管理

### 里程碑 3：补队列

你应该自己把当前“inline decode”改成更像播放器内核的结构：

- tag -> packet queue
- decode thread
- frame queue

这样你才能真正学到：

- 背压
- 缓冲
- 线程边界
- 实时流播放里的生产者/消费者模型

### 里程碑 4：补 A/V sync

这是直播播放器最值得你自己写的一段之一。

你后面应该亲手补：

- PTS/DTS 的使用
- 音频时钟
- 视频时钟
- 以谁为主时钟
- 视频帧该等多久、该丢哪些帧

## 8. 一个实际地址例子怎么理解

假设外部直播服务器 IP 是：

```text
192.168.99.128
```

外部服务端已经实现：

- RTMP ingest
- HTTP-FLV output

那当前链路可以理解成：

```text
推流地址
rtmp://192.168.99.128/live/room1

看播地址
http://192.168.99.128:8080/live/room1.flv
```

当前 Qt 直播页里填写的是：

```text
http://192.168.99.128:8080/live/room1.flv
```

这里仍然要强调：

- 当前仓库没有自建 RTMP ingest
- 当前仓库没有自建 HTTP-FLV 服务
- 当前仓库的角色是消费外部 HTTP-FLV 流

## 9. 如何验证当前改动

建议按这个顺序验证：

1. 先确认外部直播服务器真的有流：
   `rtmp://192.168.99.128/live/room1`

2. 再用外部播放器确认 HTTP-FLV 可播：
   `ffplay http://192.168.99.128:8080/live/room1.flv`

3. 如果 `ffplay` 能播，再打开 Qt 客户端直播页，输入：
   `http://192.168.99.128:8080/live/room1.flv`

4. 点击 `Start Watch` 后，重点观察：
   - 状态是否从 `Idle -> Connecting -> Reading -> Playing`
   - 日志里是否出现 `FLV header validated`
   - 日志里是否出现 `AVC sequence header observed`
   - 日志里是否出现 `Manual live video path reached the first decoded frame`
   - 页面是否真的出视频首帧

5. 如果停在 `Connecting`，优先排查：
   - URL
   - 端口
   - 网络连通性
   - 外部 HTTP-FLV 服务是否真的正常返回

6. 如果到了 `Reading` 但没到 `Playing`，优先排查：
   - FLV Header 是否正确
   - 是否真的收到 video tag
   - 是否真的收到 AVC sequence header
   - `videoCodecId` 是否为 7
   - `avcodec_open2(H.264)` 是否成功

7. 如果到了 `Playing` 但画面异常，优先排查：
   - `avcodec_receive_frame()` 是否稳定产帧
   - 输出像素格式是否需要 swscale
   - `VideoOpenGLWidget::presentFrame()` 是否正常收到三平面

## 10. 一句话总结

当前直播 HTTP-FLV 主链路已经从：

```text
HTTP-FLV URL
-> 黑盒播放器
-> 内部 demux/decode/render
```

改成了：

```text
HTTP-FLV URL
-> Qt 读取 chunk
-> 手写 FLV tag 拆包
-> FFmpeg H.264 解码
-> AVFrame
-> OpenGL 渲染
```

这版代码已经足够让你真正学习到：

- chunk 是怎么来的
- tag 是怎么拆出来的
- sequence header 在哪里接 decoder
- 普通媒体 payload 在哪里进入 FFmpeg
- 解码后的帧怎么进页面

但它还只是直播播放器学习路径的第一阶段，AAC、音频输出、队列、A/V sync 这些关键内容，应该继续由你亲手补上。
