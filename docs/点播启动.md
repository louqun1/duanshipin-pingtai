# 点播启动

## 1. 文档目标

这份文档只解决一件事：

- 如何在 Ubuntu 虚拟机里编译并启动当前点播服务端

它面向当前项目的第二阶段落地方式：

- Windows 宿主机运行 Qt 客户端
- Ubuntu 虚拟机运行 MySQL、Redis、MinIO、API、Worker、Importer

如果你还没完成基础设施部署，先看：

- [点播第一阶段部署.md](/d:/itffmpeg/av_media/online/duanshipin-pingtai/docs/点播第一阶段部署.md)

如果你想看整体方案背景，再看：

- [点播.md](/d:/itffmpeg/av_media/online/duanshipin-pingtai/docs/点播.md)
- [点播第二阶段.md](/d:/itffmpeg/av_media/online/duanshipin-pingtai/docs/点播第二阶段.md)

## 2. 当前部署约定

默认约定如下：

- Ubuntu 虚拟机 IP：`192.168.99.128`
- 项目目录：`~/vod-platform`
- 服务端目录：`~/vod-platform/server`
- API 对外地址：`http://192.168.99.128:8080`
- MinIO API：`127.0.0.1:9000`
- MySQL：`127.0.0.1:3307`

当前代码已经按下面这个思路工作：

- 客户端拿到的 `playUrl` 不再直接指向 MinIO 的 `9000`
- `playUrl` 应该指向 API 自己的 `/vod/...`
- `coverUrl` 应该指向 API 自己的 `/image/...`
- API 再用自己的 MinIO 凭据读取对象并返回给客户端

也就是说，虚拟机里最终返回的播放地址应该类似：

```text
http://192.168.99.128:8080/vod/video/1/hls/index.m3u8
```

而不是：

```text
http://192.168.99.128:9000/vod-media/video/1/hls/index.m3u8
```

## 3. 虚拟机准备

先安装必要工具：

```bash
sudo apt update
sudo apt install -y git curl unzip ffmpeg golang-go
```

检查工具是否可用：

```bash
go version
ffmpeg -version
ffprobe -version
```

如果 `go` 不在你习惯的版本上，也可以使用你自己安装的 Go，并把它加入 `PATH`：

```bash
export PATH=/usr/local/go/bin:$PATH
hash -r
go version
```

---

## 4. 项目目录

确保虚拟机里的目录结构至少包含：

```text
~/vod-platform/
  server/
  docs/
  frontend/
```

进入服务端目录：

```bash
cd ~/vod-platform/server
```

---

## 5. Go 依赖准备

先设置 Go 代理：

```bash
go env -w GOPROXY=https://goproxy.cn,direct
go env -w GOSUMDB=sum.golang.google.cn
```

然后拉取依赖：

```bash
cd ~/vod-platform/server
go mod tidy
```

如果当前网络环境访问校验服务有问题，可以临时关闭校验：

```bash
go env -w GOSUMDB=off
go mod tidy
```

查看当前配置：

```bash
go env GOPROXY
go env GOSUMDB
```

## 6. 编译服务端

在虚拟机中执行：

```bash
cd ~/vod-platform/server

mkdir -p build

go build -o build/api ./cmd/api
go build -o build/worker ./cmd/worker
go build -o build/importer ./cmd/importer
```

编译完成后检查：

```bash
ls -l build
```

正常情况下应看到：

```text
build/api
build/worker
build/importer
```

如果你只是临时调试，也可以不先 `go build`，直接运行：

```bash
go run ./cmd/api
go run ./cmd/worker
go run ./cmd/importer --help
```

## 7. 运行环境变量

当前项目最关键的环境变量是 `PUBLIC_BASE_URL`。

它必须指向虚拟机里的 API 地址，而不是 MinIO 地址。

推荐先在当前 shell 导出：

```bash
export HTTP_ADDR=:8080
export PUBLIC_BASE_URL=http://192.168.99.128:8080

export MYSQL_DSN='vod_user:vod_pass_123@tcp(127.0.0.1:3307)/vod_platform?charset=utf8mb4&parseTime=True&loc=Local'

export MINIO_ENDPOINT=127.0.0.1:9000
export MINIO_ACCESS_KEY=minioadmin
export MINIO_SECRET_KEY=minioadmin123
export MINIO_USE_SSL=false

export MINIO_RAW_BUCKET=raw-media
export MINIO_VOD_BUCKET=vod-media
export MINIO_IMAGE_BUCKET=image-assets
```

如果你想让这些变量长期生效，可以写入 `~/.bashrc`：

```bash
cat >> ~/.bashrc <<'EOF'
export HTTP_ADDR=:8080
export PUBLIC_BASE_URL=http://192.168.99.128:8080
export MYSQL_DSN='vod_user:vod_pass_123@tcp(127.0.0.1:3307)/vod_platform?charset=utf8mb4&parseTime=True&loc=Local'
export MINIO_ENDPOINT=127.0.0.1:9000
export MINIO_ACCESS_KEY=minioadmin
export MINIO_SECRET_KEY=minioadmin123
export MINIO_USE_SSL=false
export MINIO_RAW_BUCKET=raw-media
export MINIO_VOD_BUCKET=vod-media
export MINIO_IMAGE_BUCKET=image-assets
EOF

source ~/.bashrc
```

如果你的基础设施由 Docker Compose 承载，先启动它们：

- MySQL
- MinIO
- API 将要监听的 `8080`

## 9. 启动 API

推荐方式：

```bash
cd ~/vod-platform/server
./build/api
```

调试方式：

```bash
cd ~/vod-platform/server
go run ./cmd/api
```

启动成功后，日志里应出现类似：

```text
api listening on :8080
```

---

## 10. 校验 API

另开一个终端执行：

```bash
curl http://127.0.0.1:8080/healthz
curl http://127.0.0.1:8080/api/videos
curl http://127.0.0.1:8080/api/videos/1
```

重点检查 `/api/videos/1` 返回里的 `playUrl` 和 `coverUrl`。

正确结果应该满足：

- `playUrl` 不为空
- `playUrl` 指向 `http://192.168.99.128:8080/vod/...`
- `coverUrl` 指向 `http://192.168.99.128:8080/image/...`

如果仍然返回 `:9000/vod-media/...`，说明你跑的还是旧版 API，需要重新编译并重启。

---

## 11. 导入视频

把要导入的视频放在虚拟机本地，例如：

```text
/home/lq/media/xxx.mp4
```

执行导入：

```bash
cd ~/vod-platform/server
./build/importer -file /home/lq/media/xxx.mp4 -title "测试视频" -desc "第一条视频"
```

调试方式：

```bash
go run ./cmd/importer -file /home/lq/media/xxx.mp4 -title "测试视频" -desc "第一条视频"
```

导入完成后，应当：

- 原视频进入 `raw-media`
- `videos` 表插入一条记录
- `transcode_jobs` 表插入一条 `pending` 任务

---

## 12. 启动 Worker

执行：

```bash
cd ~/vod-platform/server
./build/worker
```

调试方式：

```bash
go run ./cmd/worker
```

Worker 会做这些事情：

- 从 `raw-media` 下载原视频
- 用 `ffprobe` 读取元信息
- 用 `ffmpeg` 生成 `m3u8 + ts + cover.jpg`
- 上传到 `vod-media` 和 `image-assets`
- 更新 `videos` 状态为 `ready`

---

## 13. 播放链路验证

Worker 跑完后，再次检查详情接口：

```bash
curl http://127.0.0.1:8080/api/videos/1
```

然后直接访问播放地址：

```bash
curl http://127.0.0.1:8080/vod/video/1/hls/index.m3u8
```

如果你要从 Windows 宿主机验证，再执行：

```bash
curl http://192.168.99.128:8080/api/videos/1
curl http://192.168.99.128:8080/vod/video/1/hls/index.m3u8
```

验证通过的标准是：

- 宿主机能访问虚拟机上的 API
- `m3u8` 能通过 API 的 `/vod/...` 路由读取到
- Qt 客户端能播放 `playUrl`

## 14. 常见问题

### 14.1 `go: command not found`

执行：

```bash
which go
go version
```

如果没有，安装：

```bash
sudo apt install -y golang-go
```

如果 Go 装在 `/usr/local/go/bin`，记得：

```bash
export PATH=/usr/local/go/bin:$PATH
hash -r
```

### 14.2 `ffmpeg: command not found`

执行：

```bash
sudo apt install -y ffmpeg
```

### 14.3 `go mod tidy` 或 `go build` 拉依赖失败

先执行：

```bash
go env -w GOPROXY=https://goproxy.cn,direct
go env -w GOSUMDB=sum.golang.google.cn
```

再重试：

```bash
go mod tidy
```

### 14.4 `playUrl` 还是 `9000`

说明当前运行的还是旧代码。

重新执行：

```bash
cd ~/vod-platform/server
go build -o build/api ./cmd/api
pkill api
./build/api
```

然后再次验证：

```bash
curl http://127.0.0.1:8080/api/videos/1
```

### 14.5 `m3u8` 返回 404

先确认这几件事：

- `worker` 是否真的跑完
- `videos` 的状态是否已经是 `ready`
- MinIO 的 `vod-media` 里是否存在 `video/{id}/hls/index.m3u8`

如果对象根本没生成，就不是 API 路由问题，而是导入或转码链路还没完成。

### 14.6 `m3u8` 返回 403

当前代码已经改成由 API 代理读取 MinIO 对象。

所以如果你访问的是：

```text
http://192.168.99.128:8080/vod/...
```

一般不应该再因为 MinIO 匿名权限而 403。

如果你访问的仍然是：

```text
http://192.168.99.128:9000/vod-media/...
```

那说明客户端或 API 仍然在使用旧地址。

```bash

```

## 16. 当前结论

当前推荐的日常启动顺序是：

1. 启动 Docker Compose 基础设施
2. 启动 API
3. 需要导入新视频时运行 Importer
4. 再运行 Worker 做转码
5. 用 `curl` 验证 API 和 `playUrl`
6. 最后在 Qt 客户端里实际播放

只要 `playUrl` 已经稳定返回虚拟机 API 的 `/vod/...` 地址，这条链路就已经从“依赖 MinIO 匿名桶”切换到了“依赖 API 代理读取”，部署会稳很多。
